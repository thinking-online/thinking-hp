## 03〜08 は、全部おなじ7ビート

6つが同じ形をしていることが大事。読者が型を1回で覚える。

```
　1　10秒テスト　　　　　その場でやらせて、必ず失敗させる
　2　なぜ出なかったか　　1行で言い切る
　3　頭の中で何が起きているか　＋図1点
　4　伸びない人の頭のなか／頭のいい人の頭のなか
　5　やり方のやり方　　　手順。何秒、何回、何を言う
　6　よくある質問1つ　　「〜のときはどうするんですか」
　7　合言葉　＋　この力が出てくるところ
```

ビート5が、この本の価値そのもの。
類書は概念で止まる。ここで手順まで書く。

ビート6は、読者が必ず引っかかるところを先回りして潰す。
これがないと、やり方を読んでも実行されない。

```
　03　捨てたところが出たら、どうするんですか
　04　3つも出てきません
　05　新しい単元で、前にやったものが1つもありません
　06　最初から本番の形でやったら、何もできません
　07　止まった場所が、自分でわかりません
　08　紙に書いたのに、やらなかったら
```

## 10秒テスト一覧

全部、その場で必ず失敗する。失敗が原理の証拠になるように作った。

```
　03　手元の参考書は何冊。やりきったのは何冊　　　→　0冊か1冊
　04　このページを閉じて、3つ言う　　　　　　　　→　出ない
　05　1週間前の晩ごはん　→　曜日・誰と・部活　　→　後から出る
　06　九九の7の段を、逆から　　　　　　　　　　　→　止まる
　07　前回間違えた問題を1つ　　　　　　　　　　　→　出ない
　08　先週やらなかったこと。そのときやる気は　　　→　あった
```

04は巻頭（数字11個）と同じ動作を、文章でやらせる。
巻頭が数字、04が文章。同じ失敗を2回、別の材料で起こす。

## 6つの力の表（02に置いた）

```
　戦略　　→　選ぶ力
　やり方　→　入れる力　つなげる力　出す力　なおす力
　量　　　→　続ける力

```
　選ぶ力　　　これ、出るの？　　　　　　　11本
　入れる力　　いま、閉じて出せる？　　　　 8本
　つなげる力　これ、前にどこで見た？　　　 6本

　なおす力　　どこで、止まった？　　　　　10本

続ける力が20本でいちばん多い。やり方を知っても続かなければ0だから。

## 追記2　2026年11月6日　巻頭ページの冒頭が、原稿から丸ごと落ちていた

表紙から第1章までを1本のPDFにまとめる作業で見つかった。

`scripts/assemble.py` が巻頭ページを取り込むとき、こう書いてあった。

```
　kan.split("---", 2)[2]
```

巻頭ページ.md の構造はこうなっている。

```
　# 巻頭ページ
　目次の前に置く。はじめには廃止し、この1本に統合した。
　---
　いきなりですが、10秒だけ、付き合ってください。……（11個の数字、本を伏せて、安心してください）
　---
　では、1つだけ、教えます。……
```

`split("---", 2)[2]` は2つ目の `---` より後ろを取る。
つまり、1つ目と2つ目のあいだ、本の冒頭134字が、ずっと落ちていた。

落ちていたのは、ここ。

```
　いきなりですが、
　10秒だけ、付き合ってください。

　10秒で、次の11個の数字を覚えきってください。

　　　1　4　9　1　6　2　5　3　6　4　9

　はい、終了。
　……本を伏せて、言えますか？

　たぶん、ほとんどの人が6個目か、7個目で、怪しくなったはずです。

　安心してください。
　まず、それが普通です。
```

本がいちばん最初に出す問いと、読者がその場で負ける場所と、
負けていいと言う1行。この本の仕掛けそのものが入っていなかった。

原稿_最新版.md は、ずっと「では、1つだけ、教えます。」から始まっていた。
文の途中から始まっていたことになる。

`split("---", 1)[1]` に直した。
見出しと編集メモだけを落として、あとは全部入る。

見出しは目次に合わせて「巻頭　10秒だけ、付き合ってください」にした。
`scripts/build_jo.py` にも同じ処理を入れた（PDFに編集メモが出ていた）。

### 教訓

序章の11個の数字への参照も、04の「巻頭では、数字でやりました」も、
全部この落ちていた部分を指していた。
参照先が本文から消えていても、参照している側は何も言わない。

本文の相互参照を直すとき（11/11〜11/13）、番号が合っているかだけでなく、
参照先がそもそも原稿に入っているかも確認する。
