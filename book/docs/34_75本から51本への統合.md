# 34　75本から51本への統合

著者の判断「75本にこだわるより、本当に大事なものにこだわって50になってもいい。
50のことという前提で、基本の基本は維持したうえでやれるようにしたい」を受けた作業の記録。

---

## 1　決めたこと

```
75本　→　51本（基本の基本8本はそのまま維持）
削った24本は、重なっている受け皿18本の中に、節として入れた
24本ぶんの中身は捨てていない。約35,500字を16,800字に圧縮して移した
```

本文字数　113,771字　→　93,293字
ページ数　392ページ　→　329ページ（四六判9.5pt・45字×16行で実測）

## 3　一緒に直したもの

```
・相互参照　18か所を51本の番号に振り直した
　　旧番号は本文ファイル内の # 番号で、企画書の番号と一致していなかった
・第1章「この力が出てくるところ」6ブロックを、51本の番号で作り直した
・項目数の表記（75個・62・50個・45個）を51にそろえた
・assemble.py のバグ　×／○の対が本文に二重に出ていた（51本中46本）
・アスタリスクの強調4か所（著者の指定で使わない）
・巻頭の半角引用符を鉤括弧に
・序章の見出しを「00」から「序章」に
```

## 4　まだ決まっていないこと

```
・表紙の数字　51か、もう1本畳んで50か
　　51本はどれも別のやり方を持っている。重なりで畳めるものは畳みきった。
　　50にするなら、重なりではなく「どれを落とすか」の判断になる。候補は
　　　a　新37 ケアレスミス＋新38 10個の間違い　を1本にする（方法としては続き）
　　　b　新43 覚えるときも、音楽をかけたままにする　を落とす
　　a は目次から「ケアレスミス」か「10個の間違い」のどちらかが消える
・3本の章（計画・終章）を、このままにするか、ほかの章に寄せるか
・マーカーは序章にしか入っていない。本文51本にも入れるか
・縦組みPDFの柱が「原稿」で固定。章名を出すなら build_tatekumi.py を直す
```
