# 過去問ポータル 開発ガイド

このファイルは kakomon-portal/ 配下を変更するAI(Cursor・Claude等)と開発者のための設計書。
作業前に必ず全文を読むこと。

## 0. 大原則

- 運用で触るのは **スプレッドシート「【過去問ポータル】DB」1枚だけ**。教材の追加・差し替え・公開・購入者管理はすべてシートで完結させる。コードの修正が要る運用は作らない。
- 生徒が開くまでの速さを最優先する。外部ライブラリ・Webフォントは入れない(index.html は1ファイル完結、目安100KB以下)。画像は「大学の画像」だけ(ドライブから遅延読み込み・16:9の枠を先に確保するので、レイアウトは動かない。画像がなくても同じ大きさの枠に頭文字を薄く出す)。
- 機能追加は運営者(てった)の指示があったものだけ。最低限から始めて、運用しながら一つずつ足す。

## 1. 全体像

```
生徒のLINE ─(LIFF)─> kakomon-portal/index.html (Netlify)
                         │ ① 前回の一覧を端末から即表示
                         │ ② 裏で GAS に1回だけ問い合わせ(boot)
                         ▼
                  Google Apps Script (Webアプリ)
                   ├ LINE IDトークンを検証
                   ├ 塾生判定 → THINKING CAMPUS の API(action=resolve) をそのまま利用
                   ├ 購入者判定 → 「利用者」シート
                   └ 一覧 → 「問題集」「教材」シート(キャッシュ済み)
                         │
                  Googleドライブ「過去問ポータル（教材PDF）」/大学/問題集名/*.pdf
                   (リンクを知っている人は閲覧・印刷・ダウンロード可。リンクはポータルにしか出さない)
```

PDF は Google ドライブのプレビューをポータル内に埋め込んで表示する。「印刷・保存」は端末のブラウザで PDF そのものを開く(LINE内ブラウザでは印刷できないため)。

## 2. 速さの設計(崩さないこと)

1. 起動時は localStorage の前回データ(kp.cache.v1)で即描画し、GAS の応答は裏で待つ。
2. GAS への問い合わせは起動時の boot 1回だけ。etag が同じなら一覧本体は返さない。
3. 一覧はシート編集のたびに版(catalogVer)が上がり、GAS側で作り直してキャッシュする(CacheService・分割保存)。
4. 検索は端末内の索引で行う(通信なし)。表記ゆれ(全角半角・カタカナひらがな・空白)は norm() で吸収。
5. LIFF SDK は描画後に動的読み込み。

## 3. 権限

| 種別 | 判定 | 見られるもの |
|---|---|---|
| staff | 利用者シートの「スタッフ」☑ | すべて(非公開も「非公開」タグ付きで表示) |
| student | THINKING CAMPUS で登録済みかつ有効 | 公開中のすべて |
| buyer | 利用者シートの「購入した問題集」「購入した大学（セット）」 | サンプル＋購入分 |
| guest | 上記以外(初回アクセスで利用者シートに自動で行が追加される) | サンプルのみ |

ロック中の問題集は一覧に鍵付きで出すが、**ファイルIDは端末に送らない**(GAS の filterCatalog_ で除外)。例外は教材の「無料公開」☑で、これだけはロック中でも送って「無料で読める」として表示する(購入の入口)。
「停止」☑ はどの種別より優先して閲覧を止める。「期限」を過ぎた購入者は guest 扱い。

## 4. API(GAS)

GET
- `action=ping` → `{ok, version, time}`
- `action=boot&token=<IDトークン>&etag=<前回etag>` →
  `{status:"ok", user:{name, role}, favs:[bookId], cfg:{title, buyUrl, lineUrl, campusUrl, newDays}, etag, catalog?}`
  - `catalog = {groups:[], kinds:[], books:[{id,g,u,uy,n,cov,kw,s,L,h}], items:[{b,k,t,f,d,h}], unis:{大学名:{i,c}}}`
  - unis: i=大学の画像のドライブのファイルID c=ひとこと(どちらも任意。表示している大学の分だけ送る)
  - books: g=グループ u=大学 uy=よみ n=問題集名 cov=対応する学部・日程 kw=検索キーワード s=サンプル L=ロック h=非公開(スタッフのみ)
  - items: b=問題集ID k=区分 t=タイトル f=ドライブのファイルID d=更新日(yyyy-MM-dd) h=非公開

POST(body は JSON 文字列。**Content-Type を付けない**。付けると CORS の事前確認で GAS が失敗する)
- `{action:"fav", token, book, on}` → `{status:"ok", on}`
- `{action:"log", token, book, title}` → `{status:"ok"}`

エラー: `{status:"unauthorized"}` / `{status:"error", reason}`

## 5. シート構成

運営が触るタブ
- **問題集**: ID(自動) / グループ / 大学 / 大学よみ / 問題集名 / 対応する学部・日程 / 検索キーワード / 公開☑ / サンプル☑ / 並び順 / メモ
- **教材**: 問題集名(選択式) / 区分(戦略編・大問別・単語帳・模試・解説・その他) / タイトル / ファイル(ドライブURL・自動) / 公開☑ / 並び順 / 更新日(自動) / メモ / 無料公開☑(ロック中の問題集でもゲスト・未購入者に見せる。戦略編は取り込み時に自動で☑)
- **利用者**: LINE表示名・LINE ID・初回アクセス・最終アクセス(自動) / 氏名メモ / 購入した問題集 / 購入した大学（セット） / 期限 / スタッフ☑ / 停止☑ / メモ
- **大学**: 大学 / 画像(ドライブURL) / ひとこと / メモ。大学の行は問題集シートから自動で足される。画像は「フォルダから取り込み」で大学フォルダ直下の画像から自動で入る(手で URL を貼ってもよい)。ひとことは大学ページの名前の下に出る
- **設定**: 項目・値・説明(LINEチャネルID、CAMPUS_API_URL、購入案内URL など)

自動で記録されるタブ(非表示): お気に入り / 閲覧ログ

ルール
- 問題集は「大学が名前を付けている入試の区分ごと」に分ける(例: 近大 公募推薦／一般前期A日程／一般前期B日程／一般後期)。試験日ごとには分けない。各問題集はその区分の過去問をもとに作る。
- 教材のタイトル・区分・並び順は**目次から取る**。目次は問題集を作るときに一緒に作る `links.txt`(形式は kakomon/README.md と 教材の納品ルール.md:「--- 見出し ---」→ タイトルの行 → URLの行)。
  PDFの表紙と同じ名前(例 `Vol.3 大問III 誤り指摘`)がそのままポータルに出る。ファイル名の q1 などは巻の番号であって大問番号ではないので、ファイル名からタイトルを推測しない。
- 目次の行の順番が並び順。区分はタイトルの語(模試・単語・戦略/分析・解説、それ以外は大問別)で自動判定(kindOf_)。`Vol0` は `Vol.0` に揃える(normalizeTitle_)。
- 同じ問題集に同じタイトルをもう一度入れると、新しい行は作らず**差し替え**になる(リンクは変わらない)。
- ドライブ上のファイル名は GAS が自動で `問題集名_タイトル.pdf` にする。「点検」でタイトルとずれていれば直す。
- 版(v2・最新版・日付)はファイル名にもタイトルにも入れない。修正版は「差し替え」で入れる。
- 問題集名は**重複禁止**(教材・購入者がこの名前で紐づくため)。名前を変えたら「点検」を実行する。
- 一度振られた問題集IDは変えない(お気に入りがIDで保存されているため)。

## 6. 運用メニュー(シート上部「過去問ポータル」)

| メニュー | 動き |
|---|---|
| フォルダから取り込み(目次どおりに登録) | **通常はこれ**。大学フォルダの直下に画像を置けば、その大学の画像として「大学」シートに登録する(差し替えは新しい画像を置くだけ。一番新しい画像が使われる)。ドライブの 大学/問題集名/ にPDFと目次(links.txt)を入れて実行 → 目次どおりのタイトル・区分・並び順で登録(公開は外した状態)。目次のタイトルが登録済みなら、置いたPDFで中身を差し替えてゴミ箱へ(リンクは変わらない)。目次にないPDFはファイル名を仮のタイトルにして知らせる |
| 教材を1つ追加・差し替え | サイドバー。差し替え=登録済みの教材を選んでPDFを入れる(Drive API v3 で同じファイルIDのまま更新)。新しく追加=区分と表紙どおりのタイトルを入れる(例外用) |
| 点検 | リンク切れ・共有設定・名前の不一致を赤く表示。更新日をドライブに合わせる |
| 今すぐ全員に反映 | 一覧の版を上げる(通常はシート編集で自動的に上がる) |
| 初期セットアップ | シート・入力規則・保存先フォルダ・編集トリガーを作る(何度実行しても安全) |

## 7. 絶対に変更してはいけない箇所(index.html)

- 定数 LIFF_ID / GAS_URL の値(設定後)
- liff.init / liff.login / idToken() のフロー(期限切れトークンを送らない処理を含む)
- post() の fetch(Content-Type を付けない)
- APIのパラメータ名・レスポンスのキー名への依存

HTML構造とCSSは自由に変更してよい。id 属性を変える場合は参照しているJSも合わせること。

## 7.5 反映の仕組み(手作業ゼロ)

- 画面(index.html): main に入ると Netlify が自動で公開。
- GAS(kakomon-portal/gas/): main に入ると GitHub Actions(.github/workflows/deploy-kakomon-gas.yml)が clasp で Apps Script に反映し、既存デプロイを新バージョンに更新(URL不変)。
- シートの構造: 列や入力規則を変えたら Code.gs の SETUP_VERSION を1つ上げる。次にシートを開いたとき onOpenInstalled が setupCore_ を自動実行する。
- 問題集の一覧: seed/books.csv が元データ。main に入ると、次にシートを開いたとき syncBooks_ が差分を反映(問題集名で突き合わせ。追加・説明などの更新・グループ「削除」の行は削除。公開・サンプル・メモは触らない。CSVにない手動追加の行は触らない)。

## 10. 大学の画像(2026/10 追加)

- 置き方: ドライブ「過去問ポータル（教材PDF）」/<大学名>/ の**直下**に画像を1枚置いて「フォルダから取り込み」。問題集のフォルダの中ではない。
- 規格: **16:9**(推奨 1600×900px)、JPEG か PNG、300KB 以下が目安。文字やロゴは中央寄りに置く(一覧のカードでは小さく、大学ページでは大きく、検索結果では親指大で同じ画像を使う)。
- 表示: ホームの大学カード・お気に入り(16:9)、大学ページの上部(大きく)、問題集ページの見出しの横・検索結果・最近見た問題集(小さく)。画像のURLは `https://drive.google.com/thumbnail?id=<ID>&sz=w<幅>` で、表示する大きさに合わせた幅を頼む。
- 画像がない大学は、同じ大きさの枠に大学名の頭文字を薄く出す(枠は空けたまま。画像を入れたらそこに入る)。読み込みに失敗したときも同じ。
- プレビュー(`?preview=1`)では、明治・中央だけ見本の画像を出し、ほかは画像なしの見え方を確かめられる。

## 11. 表示名とトップ画像(2026/10 追加)

- 生徒に見せる名前は **THINKING 合格部屋 ／ 学部別対策ライブラリー**(画面上部・ページタイトル・設定シート「ポータル名」)。コード・シート・フォルダの内部名(過去問ポータル)は変えない(運用とリンクを壊さないため)。
- トップ画像は `kakomon-portal/img/top-800.webp`・`top-1400.webp`(16:9。端末の幅に合わせて小さい方から読む。先読み指定あり)。差し替えるときは同じ名前・同じ比率で上書きする(800px 幅で約50KB、1400px 幅で約120KB が目安)。
- ホームの並び: トップ画像 → ひとこと(何がそろっている場所か) → (ゲストには登録・購入の案内) → お気に入り(1冊以上あるときだけ) → 大学から探す。グループのタブを切り替えても画面は上に戻らない。
- 検索: 画面右下の虫眼鏡ボタン（いつも表示）を押すと、その場で左へ横に伸びて検索窓になり、すぐ入力できる。右端の × で元の丸に戻る（入力も消える）。結果から問題集を開いたときも自動で閉じる。キーボードが出たら visualViewport でキーボードのすぐ上に持ち上げる。ページの下は虫眼鏡に隠れないように余白を取っている。
- 大学の画像は2通りで出せる。①シート「大学」の画像欄（ドライブ。運営が差し替えるとき）②リポジトリの `kakomon-portal/img/uni/<名前>-640.webp`・`-1280.webp` と index.html の `UNI_IMG`（大学名 → 名前）。①があれば①を優先する。②は Netlify から配るので速い。

## 12. 確認用リンク（LINEログインなし）
- `https://thinking-online.com/kakomon-portal/?k=<キー>` で、LINEログインなしに「塾生の表示」「未購入者（ゲスト）の表示」を開ける。スタッフの確認用。
- キーは設定シートの「確認用リンク（塾生の表示）」「確認用リンク（未購入者の表示）」で決まる。値が64桁の16進ならキーの SHA-256、それ以外はキーそのもの。「停止」と入れると無効になる。
- リンクが外に漏れたときは、設定シートの値を新しい文字列（16文字以上）に書きかえる。新しいリンクは `?k=<その文字列>`。
- このリンクでは、お気に入りは端末の中だけに保存し、閲覧ログは残さない。キーそのものはリポジトリに置かない（コードにあるのはハッシュだけ）。

## 13. ロック中の問題集の目次
- 見られない問題集でも、公開中の教材の区分とタイトルだけを送る（`L: 1`、ファイルIDは送らない）。画面では鍵マーク付きで並べ、押しても開かない。
- 無料公開の教材（`fr`）は今までどおり開けて、「無料」の印が付く。
- 一覧の形を変えたときは `CATALOG_FORMAT` を1つ上げる（etag に入るので、端末に残った古い一覧が取り直される）。
- 左上の「THINKING 合格部屋」を押すとホームに戻る（ホームにいるときは一番上に戻る）。

## 14. 教材の共有について（2026/10）
- 教材を共有しない仕組み（GAS が中身を渡して pdf.js で表示・透かし・印刷用の合言葉）を一度入れたが、表示が重くなること・印刷の手間から運営の判断で戻した。
- 今は以前どおり、教材のPDFは「リンクを知っている人は見られる」で、ポータルはドライブの表示を埋め込む。印刷・保存はドライブのPDFを開く。
- 一度止めた共有は、SETUP_VERSION 11 の自動セットアップ（シートを開いたとき）と「点検」で元に戻る。
- ホーム・問題集ページ・ビューアの下に、共有・転載・譲渡の禁止の表記を出している。

## 15. 画像の出し方（ちらつき対策）
- 一度読み込んだ画像は覚えておき（`PIC_SEEN`、端末にも保存）、描き直すときはフェードせずにそのまま出す。
- 本物の画像が届くまで、横32pxのぼかしの下絵（`PIC_LQ`）を敷く。大学の画像を足したら `python3 scripts/kakomon-portal-lqip.py` を1回実行して下絵を作り直す（index.html の LQIP:BEGIN〜END を書きかえる）。
- ホームを出したあと、手が空いたときに全大学のカード用の画像（640px）を先に読んでおく（`prefetchPics`）。
- `/kakomon-portal/img/*` は端末に1日ためる（netlify.toml）。

## 16. 「やった」チェックと利用状況のまとめ
- 教材の右の「やった」を押すとチェックが付き、問題集ページに進み具合（○ / ○）、問題集の一覧に小さなバーが出る。
- 保存はお気に入りと同じ考え方：シート「やった」（非表示）に LINE ID・問題集ID・ファイルID・教材・日時。起動の1回の通信（boot）で `done` として返す（GAS で6時間キャッシュ）。押したときは画面をすぐ変え、保存は裏で送る。確認用リンクでは端末の中だけに保存。
- 閲覧ログ（非表示）の種別：visit＝その日はじめて開いた（1人1日1行）、book＝問題集のページを見た、view＝教材を開いた、search0＝検索で見つからなかった言葉。「区分」列に塾生・購入者・ゲスト・スタッフを残す。
- 毎週月曜7時（時間で動くトリガー `weeklyReport`）に「利用状況」シートを作り直す：来た人（区分ごと）、閲覧数と前の週との比較、問題集ごとの閲覧（うちゲスト＝購入見込み）、大学ごと、検索で見つからなかった言葉、「やった」の数。「利用状況（週ごと）」には毎週1行ずつ足していく。まとめたあと、閲覧ログは直近2週間より古い行を消す（数字は週ごとのシートに残る。生の記録は持たない）。メニュー「利用状況のまとめを今すぐ作る」でいつでも作れる（このときは週ごとの行は足さない）。
- 生徒ごとの進み具合：メニュー「生徒ごとの進み具合を一覧にする」で「生徒ごとの進み具合」シートを作り直す（毎週のまとめでも作り直す）。名前は「利用者」シートの氏名メモ → 最後にチェックしたときのLINEの表示名の順。フィルタで名前や問題集を絞れる。

## 0. 運営からの決まり（いちばん優先）
- **重くしない**：表示・起動・スプレッドシートのどれも重くなる仕組みは入れない。新機能は「重さゼロ／ほぼゼロ」で作れるものだけにする。
- 新しい仕組みは、方向性を運営に確認してから作る。
- データは本当に必要なものだけ残す（閲覧ログは2週間で消す。生徒の「やった」は残す）。

## 17. 修正依頼・前回のつづき・志望校
- **修正依頼**：教材を見る画面の「修正を依頼」から。問題集・教材・送った人（LINEの名前・区分）は自動。生徒はページ・種類（誤字・脱字／答えが違う／解説が分かりにくい／表示されない／その他）・内容・写真3枚まで。写真は端末で長い辺1280pxのJPEGに縮めてから送る。GAS は「修正依頼」シートに1行（状態は未対応／対応中／対応済み／対応しない）、写真は塾のドライブ「修正依頼の写真」（共有しない）。1人1日10件まで。シートを開いたときに未対応の件数を知らせる。メール通知は、権限の承認をやり直す必要があるため入れていない。
- **前回のつづき**：最後に開いた教材を端末の中だけに覚え（`kp.last.v1`）、ホームの上に出す。通信なし。
- **志望校**：一度入れたが、志望校が複数あるとホームが問題集で埋まるため、運営の判断でやめた。
- **修正依頼の結果**：「修正依頼」シートの「状態」と「生徒へのひとこと」を入れると、依頼した本人のポータルに出る。ホームの上に「✔ 修正しました／確認しました」のお知らせ（1回表示したら見たことにして、次に開いたときは出さない・端末に記録）、ホームの「送った修正依頼（○件）」から一覧（状態：確認中／修正しました／このままにします）。boot の `reqs` で返す（シートが編集されるまで GAS でキャッシュ。起動の通信は1回のまま）。直した教材に全員向けの印は付けない（運営の判断）。
- 「修正依頼」シートの形：1行目＝件数のまとめ（未対応・対応中・対応済み・対応しない。式で自動）、2行目＝見出し（フィルタ付き・固定）、3行目から依頼。状態で行の色が変わる（未対応＝赤、対応中＝黄、対応済み／対応しない＝灰色の文字）。古い形（1行目が見出し）は SETUP_VERSION 15 で上に1行足して作り直す（`reqSheet_`）。
