# 英語設計診断（/shindan/eigo/）

学年別・全10問の**「英語の読み方」診断**。診断結果をコピーしてLINEに送ってもらい、
そのリストをもとに個別面談 → 英語講座へつなげるための入口ページ。

- 公開URL: `https://<サイトドメイン>/shindan/eigo/`（フォルダ直下の index.html がそのまま配信される）
- 依存なし・単一HTMLファイル。ビルド不要。

## 診断コンセプト（ここが他と違う）

文法・単語の暗記クイズは1問も出さない。全問が共通の問い——**「この英文を、正しく読めたか？」**

- **構造把握（str）**: 文が長くなっても「誰が・何を・どうした」が取れるか。主節の特定、修飾のかかり先、挿入・省略・倒置。
- **言い換え（para）**: 読んだ内容の正確な言い換えを選べるか。誤答は**主客反転・肯否反転・因果反転・時系列ずらし・本文にない情報**で作るので、「なんとなく読み」では選べない。
- **論理・文脈（logic）**: 接続詞・指示語・譲歩・具体例の役割。文と文のつながりを追えているか。

学年で変わるのは**英文の長さ・節の深さ・語彙レベルだけ**。診断の方針は中1から既卒まで共通。

## 「なんとなく」を検出する2つの仕掛け

1. **1問ごとの制限時間**（問題ごとに40〜110秒、データの `t`）。時間切れは未回答（−）として自動送信。
   じっくり調べながら解く「その場しのぎ」を防ぎ、実力の読解速度ごと測る。
2. **全問に5つ目の選択肢「わからない」**。勘で選んだ誤答（×）と正直な「わからない」（？）を区別する。
   ここから **回答の質**（正解／誤答／わからない／時間切れ）が出て、
   「わからないを選ばずに誤答が多い」＝**感覚読み型**という、面談で一番刺さる診断が可能になる。

## 導線設計（全体フロー）

1. スタート（ルール説明つき）→ STEP1 学年（7分岐）→ STEP2 志望校 → STEP3 英語偏差値
2. 全10問（易→難の傾斜。学年別6セット、既卒は高3セット）
3. 結果シート（スコア／タイプ／3分野グラフ／回答の質／弱点単元）
4. **送信CTA**: タイプ表示の直下（一等地）に「①結果をコピーする → ②LINEを開いてそのまま送信」を
   大きく配置＋画面下に追従バー（スクロール中も常時表示）。LINEボタン押下時にも自動コピーが走る保険つき。
   リターンは「送ってくれたら、今の状態と“やるべきこと”を個別に整理して返します」（処方箋の自動表示はしない。
   個別対応そのものを送信の動機にする）
5. 結果画面下部に **「英語読解力キャンプ」モニター募集バナー**（8/9スタート・5日間・
   フォロワー9万人突破記念・最初で最後の企画）。「診断結果と一緒に『キャンプ希望』と送って」で
   送信動機を二重化
6. 送られてくるテキスト: 学年・志望校・偏差値・スコア・タイプ・3分野正答率・
   **回答の質（正解/誤答/わからない/時間切れの内訳）**・弱点単元・**1問ごとの正誤（○×？−）**・診断コード

## 配点・レベル・タイプ

- 各問に難度 `d`（1/2/3）。配点は **d1=8点・d2=10点・d3=12点**。
  各学年 d1×3＋d2×4＋d3×3 ＝ **100点満点**。満点は最難問3問（d3）を含む全問正解でのみ出る。
- Lv5: 88〜 ／ Lv4: 70〜 ／ Lv3: 50〜 ／ Lv2: 30〜 ／ Lv1: 〜29
- タイプ判定（優先順）:
  1. **実戦設計型**: スコア85以上かつ3分野すべて70%以上
  2. **感覚読み型**: 誤答4問以上 かつ「わからない＋時間切れ」1問以下 かつ スコア75未満
     （＝根拠なく選んで外している行動パターン）
  3. **基礎再設計型**: 2分野以上が正答率50%未満
  4. それ以外: 最も正答率の低い分野 → **構造ブラックボックス型／読み違い型／論理迷子型**

## 問題設計ポリシー（ここが命）

各学年10問 ＝ **構造把握3／言い換え4／論理・文脈3**（d1×3・d2×4・d3×3）。

1. **全問に対象英文 `s` をつける**。設問は「正しく読めたか」だけを問う。知識の想起で解ける問題は作らない。
2. **言い換え問題の誤答は「要素の反転」で作る**:
   - 主客反転（AがBに → BがAに）／肯否反転（unaware → aware）／因果反転（原因と結果の入れ替え）
   - 時系列ずらし（before/after、回数）／場所ずらし／本文にない情報の混入
   - 誤答にも本文の単語を散りばめ、「単語の拾い読み」では選べないようにする
3. **構造問題は文構造そのものを問う**: 主節はどれか、S/Vはどれか、修飾はどこに掛かるか、挿入・省略・倒置。
4. **論理問題は必ずマーカーか指示語を軸にする**: However / so / for example / in other words / 譲歩、it / this / one。
5. **正解は必ず1つに定まること**。「最も近い」形式では、誤答は必ず本文と明確に矛盾する要素を1つ以上含むこと。
6. **英文の文法・語彙は「その学年の8月時点で既習」の範囲に限定**。難しくするのは
   文の長さ・節の深さ・言い換えの精密さであって、未習文法ではない。
   - 中1: be動詞・一般動詞・can・疑問詞まで ／ 中2: 過去・未来・不定詞・接続詞まで
   - 中3: 現在完了・受動態・不定詞応用まで ／ 高1: 5文型・時制・助動詞・受動態まで
   - 高2: 関係詞・比較・準動詞・仮定法過去まで ／ 高3・既卒: 全範囲
7. **制限時間 `t` は「1〜2回精読＋選択肢照合」で解ける長さ**に設定（40〜110秒）。
   考えれば解ける、が、辞書や調べ直しの余裕はない、が基準。
8. データ上は `a:0`（先頭が正解）で統一し、表示時にシャッフル。「わからない」はコードが自動付与。

## 問題QCチェックリスト（追加・変更したら必ず全項目）

- [ ] 正解が1つに定まるか（誤答が本文の解釈として成立しないか、ネイティブ視点でも確認）
- [ ] 正解選択肢が本文を過不足なく言い換えているか（言いすぎ・言い足りずがないか）
- [ ] 英文・英語選択肢の文法と語彙が、その学年の8月時点で既習範囲か
- [ ] 本文を読まなくても常識や単語知識だけで選べてしまわないか
- [ ] 誤答がそれぞれ「特定の読み違い」（主客・肯否・因果・時系列）を検出する設計か
- [ ] 制限時間が適切か（短すぎて実力が出ない／長すぎて調べ読みできる、の両方を排除）
- [ ] 和訳・選択肢の日本語が英文と正確に対応しているか
- [ ] 単元名 `u` が結果画面・LINEテキストに出て意味が通るか

## 面談側の読み方（送られてきたテキスト）

- **「回答の質」行が最重要**。
  - 誤答が多く「わからない」が少ない → 感覚読み。根拠を持つ読み方の指導がそのまま提案になる
  - 「わからない」が多い → 正直で自己認識が高い。伸ばす場所が明確
  - 時間切れが多い → 読み方の手順が未確立。速読より精読の型から
- 「正誤：○×？−」は出題順と対応。×の位置と `QUIZZES` を突き合わせれば、
  どの読み方（構造/言い換え/論理）のどの難度で落ちたかが1人ずつ特定できる。
- 診断コードは全員共通の固定値 **TH-ENG-A8BK**（index.html の `DIAG_CODE`）。
  コピー文面に必ず含まれるため、**Lステップの自動応答キーワード**に「TH-ENG-A8BK」を設定すれば
  診断結果の送信に自動反応できる。コードを変えたらLステップ側のキーワードも合わせること。
