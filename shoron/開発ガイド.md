# 小論文ポータル（THINKING 小論文ラボ）開発ガイド

このファイルは shoron/ 配下を変更するAI(Cursor・Claude等)と開発者のための設計書。
作業前に必ず全文を読むこと。

## 0. 大原則

- 使い方は1つ：**生徒が「問題」と「自分の答案」を送る → それをもとに添削が作られる**。塾が課題をあらかじめ登録する仕組みは持たない（運営の判断。シンプルにするため）。
- この場所の目的は「生徒が次の1本で確実に良くなること」。点を付けることではない。機能はこの目的に効くものだけを足す。
- 生徒の答案・AIの下書き・講師が直した最終版・質問のやりとりは、すべてスプレッドシートに残す。消さない。
- AI の下書きは、既定では生徒に見せない。講師が直して「返却」したものだけが生徒に見える。
- 機能追加は運営者(てった)の指示があったものだけ。

## 1. 全体像

```
生徒のLINE ─(LIFF)─> shoron/index.html (Netlify)
                         │ 起動時に boot を1回。提出・質問は POST
                         ▼
                  Google Apps Script (Webアプリ) shoron/gas/Code.gs
                   ├ LINE IDトークンを検証 → 利用者シート／THINKING CAMPUS で権限を決める
                   ├ 問題と答案を「提出」シートに1行で保存（写真・PDF はドライブ。共有しない）
                   ├ 1分おきのトリガー processQueue → Claude API で下書き（「AI下書き」列）
                   └ 講師が直して返却（「添削」列）→ 生徒の画面に出る
```

流れ: 問題と答案を送る（写真・PDF・文字のどれでも） → AI が問題と答案を読んで下書き → 講師が直して返却 → 生徒が読む・質問する → 書き直して再提出（前回との差が出る）

## 2. 精度の考え方（崩さないこと）

1. **点は AI に付けさせない**。AI と講師が決めるのは観点ごとのレベル（1〜5）だけ。総合点は「観点」シートの学部別の配点から GAS が計算する（`total_`）。画面側の `calcTotal` は同じ計算の写し。片方を変えたら両方変える。
2. **レベルには記述がある**。「観点」シートのレベル5・3・1の文が採点の物差し。AI にも講師の画面にも同じ文が出る。
3. **AI は生徒が送った問題そのもの（写真・PDF）を読んでから答案を読む**。問題が一部しか写っていない・読めないときは、総評の最後に「（講師確認：…）」と書かせている。答案が手書きの写真のときは先に文字に起こし（`read_`）、題名・設問・字数の上限も一緒に読み取ってシートに入れる。
4. **生徒の履歴を AI に渡す**。直近4本の点・弱点タグ・最優先の改善と、書き直しなら前回の答案。AI は「前回の指摘がどうなったか」（followup）を書く。
5. **弱点タグは語彙を固定**（Code.gs の `TAGS`）。自由記述にすると「くり返している弱点」を数えられない。足すときは Code.gs と mock.js の両方。
6. **行内コメントの引用は答案の文字列そのまま**。本文に見つからない引用は `cleanReview_` が落とす。
7. **AI の下書きと講師の最終版を別の列に残す**。両者の差が、プロンプトと観点を直す材料になる。
8. 配点・レベルの記述は塾が作った仮のもの。大学の公式の採点基準ではない。運営がシートで直す。

## 3. 権限

| 種別 | 判定 | できること |
|---|---|---|
| staff | 利用者シートの「講師」☑ | すべての提出を見る・添削・返却 |
| student | 利用者シートの「受講」☑、または THINKING CAMPUS で有効 | 問題と答案を送る、自分の添削、質問 |
| guest | 上記以外（初回アクセスで利用者シートに行が自動で入る） | 案内だけ（送れない） |

「停止」☑ はどれより優先して guest にする。

## 4. API（GAS）

GET `action=ping` → `{ok, version, time}`

POST（body は JSON 文字列。**Content-Type を付けない**。すべてに `action` と `token`）

- `boot` → `{status, user:{name, role, target, uid}, cfg, rubric, tags, facs, subs}`
- `submit {q, probFiles[], uni, fac, year, limit, text, photos[], memo}` → `{status, id}`（新しい問題）
- `submit {root, text, photos[], memo}` → `{status, id}`（書き直し。問題は元の提出のものを使う）
  - probFiles / photos は data URL（JPEG・PNG。問題は PDF も可）。画面側で長い辺1600pxに縮めてから送る
- `ask {sub, text}` → `{status, qa}` / `seen {sub}`
- 講師のみ: `queue` → `{subs, students}` / `saveReview {sub, review, back}` / `aiDraft {sub}` / `note {uid, text}`

提出（subs）の形: `{id, at, state:"wait"|"done", name, uni, fac, year, title, q, limit, probFiles(点数), ver, chars, text, memo, root, prev, back, seen, qa, photos(枚数), review?}`。
`root` は同じ問題の最初の提出のID（書き直しをまとめる鍵）。
講師には `uid, raw（シートの状態）, draft（AIの下書き）, probUrls, photoUrls, aiNote, teacher` が加わる。

添削（review / draft）の形:
`{scores:[{k, lv, why}], total, band, summary, strengths[], priorities:[{t, why, how}], inline:[{q, kind:good|issue|rule, c, fix}], outline:[{role, note}], rewrite, tags[], followup:[{tag, state:improved|same|worse, note}], next, teacher}`

エラー: `{status:"unauthorized"}` / `{status:"denied", reason}` / `{status:"error", reason}`

## 5. シート構成

- **提出**: 1提出1行。状態（提出済→AI下書き済→返却済、AIエラー）、大学・学部・年度・題名、総合点・評価・観点ごとのレベル・弱点タグ（集計用に列で持つ）、本文（答案）、設問、字数上限、問題のファイル（ドライブURL）、答案の写真、AI下書き(JSON)、添削(JSON)、講師、返却日時、既読、LINE ID、元の提出ID、前の提出ID
- **質問**（非表示）: 日時 / 提出ID / 誰 / 名前 / 本文
- **利用者**: LINE表示名 / LINE ID / 氏名 / 志望学部 / 受講☑ / 講師☑ / 停止☑ / 講師メモ
- **観点**: キー / 観点 / 見るところ / レベル5・3・1 / 学部ごとの配点（既定・文・法・経済・商・総合政策・環境情報）。キーは変えない
- **設定**: ポータル名、LINEチャネルID、AI下書き（自動／手動／オフ）、AIモデル、返却のしかた、1日の提出上限 など

生徒が送った問題の写真・PDF は塾のドライブ「小論文ポータル（問題と答案）」に入る。共有はしない（講師は塾用アカウントでリンクを開く）。添削のための利用にとどめ、ほかの生徒に配らない。

## 6. AI（Claude API）

- キーは Apps Script のスクリプト プロパティ `ANTHROPIC_API_KEY`。シートにもリポジトリにも置かない。
- `aiReview_` が1提出につき1回呼ぶ。出力は構造化出力（`REVIEW_SCHEMA`）で受け、`cleanReview_` で形をそろえる。
- AI に送るのは生徒が送った問題（写真・PDF・文章）・観点・答案・過去の添削の要点・生徒のメモ。**氏名と LINE ID は送らない**。
- 答案が手書きの写真のとき・題名がないときは、先に `read_` で読み取って「本文」「題名」「設問」「字数上限」に入れる。
- 講師向けの指示文は `AI_SYSTEM`。直すときは、講師が下書きをどう直したか（AI下書き列と添削列の差）を見てから直す。

## 7. 絶対に変更してはいけない箇所（index.html）

- 定数 LIFF_ID / GAS_URL の値（設定後）
- liff.init / liff.login / idToken() のフロー
- api() の fetch（Content-Type を付けない）
- APIのパラメータ名・レスポンスのキー名への依存

## 8. 反映の仕組み

- 画面: main に入ると Netlify が自動で公開。
- GAS: main に入ると GitHub Actions（deploy-shoron-gas.yml）が clasp で反映（`SHORON_SCRIPT_ID` / `SHORON_DEPLOYMENT_ID` が未設定のあいだは何もしない）。
- シートの構造を変えたら Code.gs の `SETUP_VERSION` を1つ上げる。次にシートを開いたとき自動でセットアップが走る。

## 9. 動作確認

- プレビュー（設定前でも見られる）: `/shoron/?preview=1&role=student`（role は student / staff / guest）。問題と答案を送る→講師で返却→生徒で読む、まで仮のデータで一通り試せる。データはそのタブの中だけ。AI の下書きは決まった文を返す見本。
- 本番: スマホのLINEで LIFF URL を開く。GAS: `<GAS_URL>?action=ping`

## 10. 今は入れていないもの

- 塾が課題を登録して配る仕組み・出題のねらいの欄（試作の最初の版にはあったが、生徒が問題ごと送る形に一本化した）
- 文字に起こした答案を講師が画面上で直す欄（今はシートの「本文」を直す）
- 提出が数千行を超えたときの読み込みの工夫（今は毎回「提出」シート全体を読む）
- 講師が複数いるときの担当割り
- 原稿用紙（縦書き・マス目）での表示
- AI下書きと講師の最終版の差の集計
