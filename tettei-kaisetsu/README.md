# THINKINGの徹底解説シリーズ（PDF）

大学・年度ごとの過去問 英語 解説 PDF を作る仕組み。
中身（Python の辞書）→ HTML → PDF（WeasyPrint）の順に組み、最後に検査する。

## 最初に守ること：中身はこのリポジトリに置かない

このリポジトリは Netlify で `publish = "."`。**ここに置いた物はすべてサイトとして公開される。**

| 置いてよい（このフォルダ） | 置かない（中身置き場へ） |
|---|---|
| `build.py`・`templates/style.css`・`README.md` | 本物の `data/<univ>_<year>.py`（解説・全訳・正解） |
| `sample/sample_dummy.py`（中身のないダミー。`"dummy": True`） | できた PDF・HTML・ページ画像 |
| `.gitignore` | 過去問の PDF・画像、照合に使った資料 |

- 中身置き場はリポジトリの外。`--content-dir` か環境変数 `TETTEI_CONTENT_DIR` で指定する。
  指定がなければ `build.py` の `DEFAULT_CONTENT_DIR`（作業用 scratchpad の `content/`）を使う。scratchpad は消えることがあるので、本番の中身は消えない外部の場所（Google ドライブ等）にも控えを置くこと。
- 置き方：`<中身置き場>/data/<univ>_<year>.py`。PDF の既定の出力先は `<中身置き場>/out/<univ>_<year>.pdf`。
- 安全装置：
  - `build.py` は `"dummy": True` でない data がリポジトリ内にあると止まる。
  - `.gitignore` で `out/`・`*.pdf`・`*.html`・`data/`・`content/` を除外している（誤って置いてもコミットされない）。

## 準備

```
pip install weasyprint fonttools
apt-get install -y fonts-noto-cjk fonts-liberation poppler-utils
fc-list | grep "Noto Sans CJK JP"     # 入っているか確認
```

使う書体：見出し・表・札＝Noto Sans CJK JP、本文・訳＝Noto Serif CJK JP、英語＝Liberation Serif。
コンテナを作り直すと Noto CJK が消えることがある。その場合 `build.py` が「フォントが見つかりません」で止まるので入れ直す。

## 作り方

```
# 見本（ダミー）を組む
python3 build.py sample/sample_dummy.py --out /path/to/sample.pdf --png /path/to/pages

# 本番：中身置き場の data/waseda-shogaku_2026.py を組む
TETTEI_CONTENT_DIR=/path/to/content python3 build.py waseda-shogaku_2026 --png /path/to/pages
```

1. `sample/sample_dummy.py` を `<中身置き場>/data/<univ>_<year>.py` に写す（例 `waseda-shogaku_2026.py`）。`"dummy"` を消し、`footer_note` を空にする。
2. 中身を書く（下の「章立て」「書き方のルール」）。
3. `build.py` で組む。`--png` でページ画像を出し、**全ページを目で見る**（表の途中で切れていないか、見出しだけがページ末に残っていないか、マス目が崩れていないか）。
4. 検査で `ERROR` が 1 つでも出たら終了コード 1。直してから出す。

### 検査の中身（build.py が自動で行う）

- 必要フォントがあるか（無ければ止まる）
- 本文の全文字が Noto CJK JP に収録されているか（豆腐の防止）
- PDF の全フォントが埋め込まれているか、想定外の代替フォントに落ちていないか（`pdffonts`）
- PDF から文字を読み戻せるか、U+FFFD（文字化け）がないか（`pdftotext`）
- 禁止語（他社の書名・シリーズ名・社名）がないか
- 英文の載せすぎ（中身の形 v2）：
  - 数える物：根拠の文（`evidence[].en`）・選択肢（`choices[].en`）・精読の構文の図（1 つ＝1 文）・下線部 `__...__`・`[[...]]`。同じ文（とその一部）の重複は 1 回だけ数える
  - 引用 1 つは原則 1 文：45 語を超えたら WARN、4 文以上も WARN、80 語超は ERROR（段落の転載）
  - 大問ごとの英語の合計 ÷ 本文語数（大問の `body_words`）が約 3 割以内：30% 超で WARN、35% 超で ERROR（本文の通し掲載の防止）
  - `body_words` が無い大問は WARN を出し、旧来の絶対上限（260 語超で ERROR）で検査する
- 出典：`source` が無い大問は ERROR。構文の図（`core`）が 4 個以上の大問は WARN
- 選択肢：`choices` に正解（`ok: True`）が無ければ ERROR。正解の記号が `answer` と食い違う・`why` が空・誤答の `who` が空・訳 `ja` が空なら WARN
- 欠け：負の `text-indent` の中にある背景・枠つきの `inline-block`、本文領域の左右からはみ出した背景・枠（レイアウト後の箱を調べる）
- 記述の答案例が指定字数に収まっているか、正解・照合欄が空でないか、根拠の文に訳 `ja` と決め手 `point` があるか

## 中身の形 v2（2026/11/18〜）

主役は「本文のどこに根拠があり、どういう手順で解くか」と「選択肢それぞれの訳と、なぜ正解・不正解か」。
SVOC の構文の図は、構造そのものが決め手になる設問に限って短く（0〜3 個/大問）。英文本文は載せない代わりに、段落ごとの全訳と「つまりどういうことか」を載せる。

## 章立て（`BOOK` 辞書の形）

| 順 | 章 | data のキー |
|---|---|---|
| 1 | 表紙 | `univ` `faculty` `year` `subject` `cover_color` |
| 2 | 目次 | 自動（ページ番号も自動） |
| 3 | この年度の全体像（大問構成・試験時間・時間配分・差がつく所） | `overview` |
| 4 | 大問ごと（`parts` の数だけ繰り返す） | `parts[]` |
|   | 出典（大問の冒頭に 1 行。**必須**） | `source`（例「The New York Times, 2025年7月26日の記事に基づく（大学の冊子の表記による）」） |
|   | 本文の概算語数（表示しない。英語量の検査に使う） | `body_words` |
|   | この文章の正体（一行） | `identity` `identity_note` |
|   | 設問タイプと攻め方 | `types` |
|   | 英文マップ（段落の流れと設問の在りか） | `map_flow` `map` `map_note` |
|   | 構文の確認（精読）：あれば設問の前に小さく出す。目次には出さない | `core[]`（0〜3 個。`lines` に 英文の区切り／働き／訳／`level`＝字下げ） `core_lead` |
|   | 設問ごとの解説 | `questions[]`（下記） |
|   | 全訳（段落ごとに 全訳 → 色を変えた「つまり」の囲み） | `translation[]`（下記） |
| 5 | 総まとめ：解答一覧（照合欄つき）・失点の型別の復習動線・自己採点表 | 自動＋`summary` `sources` |

設問 1 つ（`questions[]` の要素）。カードの中は「出題意図 → 手順 → 根拠の文 → 全選択肢の検討 →（記述・整序なら）採点の要素・答案例・減点」の順に出る：

- 共通：`id` `type` `answer` `points` `checked`（照合結果） `target`（下線部・設問の要約） `miss_types`（失点の型のキー）
- `intent` 出題意図 / `steps` 解く人の頭の中の手順（番号つき。「どこを読む → 何に気づく → どう絞る → どう確かめる」）
- `evidence[]` 根拠の文（v2）= `loc`（「第4段落第2文」）・`en`（根拠の英文。原則 1 文、必要なら前後 1 文まで）・`ja`（その訳）・`point`（どの語句が、なぜ決め手か）。
  `en` と `ja` は左右に並べて出る。`en`・`ja` の中の `**…**` は決め手の語句として蛍光ペンで強調される（英文と訳の対応する所の両方に付ける）。`basis` があれば根拠の文の上に一行のまとめとして出る
- `choices[]` 全選択肢（v2。選択式・会話・語彙・内容一致・接続語・表題など）= `key`（記号）・`en`（選択肢の英語そのまま）・`ja`（訳）・`ok`（True／False）・`why`（正解ならなぜ正解か／不正解なら本文のどことどうずれるか）・`who`（不正解のみ：これを選ぶ人は何ができていないか・どういう思考で来るか）。
  表で出る：正解の行は緑（○）、誤答は朱の ×。各行に英語・訳・理由、誤答は「選ぶ人の思考」も
- 整序・記述は `choices` の代わりに `answer`・`examples`・`ng` を使い、`evidence` と `steps` を充実させる
- 記述：`rubric[]`（採点の要素・配点・判定） `chars`（字数。マス目が出る） `examples[]`（答案例） `ng[]`（減点される書き方）
- 旧キーとの関係：`choices` がある設問では旧の誤答表 `wrong[]` は出さない（重複させない）。`evidence` がある設問では旧の「正解の根拠」囲み（`basis` のみ）は出さず、`basis` は根拠の文の囲みの冒頭に入る。v2 のキーが無い旧データは従来どおり `basis`・`wrong[]` で組む

全訳（大問の `translation[]` の要素）：

- v2：`para`（段落番号。数字なら「第N段落」、会話の発話などは「発話1」のように文字列をそのまま見出しにする）・`label`（役割、任意）・`qs`（関係する設問、任意）・`full`（その段落の全訳。文頭に ①②…）・`gist`（つまりどういうことか。2〜4 文で言い換え・背景・論理のつながりを補う）
- 旧データ（`sentences[]` に `faithful`・`plain` の文単位 2 列）はそのまま従来の表で組む（互換）。旧データを v2 に写すときは、`full` ＝忠実訳をつなげたもの、`gist` ＝かみくだいた訳を「つまり」の形に書き直したもの

解答一覧・自己採点表・復習動線の「該当設問」は `questions` から自動で作る（正解を二か所に書かない）。

## 書き方のルール

- **問題文・英文本文は載せない。** 生徒は問題冊子を印刷して手元に置いて使う。英語の引用は根拠の文（`evidence`）・下線部・選択肢（と、あれば精読の数文）だけ。引用 1 つは原則 1 文、大問の英語は本文語数の約 3 割まで（`build.py` が数える）。
- **全訳は THINKING のオリジナル。** 市販の解答資料・他サイトの訳を写さない、言い換えて使わない。自分で英文から訳す。
- **照合資料の扱い。** 正解は自分で解いて決め、そのあと大学公表の解答・市販の解答資料と照合する。照合欄（`checked`）には「一致」「不一致（相手の解答と、こちらが採った根拠）」「公表なし」を書く。他社の書名・シリーズ名・社名は書かず「市販の解答資料」と総称する（表紙にも本文にも入れない。`build.py` が検査する）。
- **推定の明記。** 配点・試験時間・採点基準など、公表資料で確かめられないものには必ず `【推定】` をつける。記述の採点の要素は原則 THINKING の推定。
- **記法。** 強調は `**太字**`、下線部の引用は `__下線__`、英語の語句は `[[...]]`、札は `【...】`（自動で色付きの太字。推定＝金、罠・注意・誤答・減点＝朱、正解・根拠・答案例・訳＝緑、ほか＝紺）。色や囲みは data に書かず、`build.py` と CSS が決める。
- **書き方の調子**（手本：リポジトリ直下の `gakushuin-university-2022-english-q2-full.html`）。
  - 「この文章の正体」は一行で、素朴な読みとの違いを言い切る（例：「観光客が悪い、ではない。犯人を途中ですり替えている文章。」）。
  - 根拠は段落番号・文番号で指す（「第9段落第3文」）。答えは下線部の外にある、という読み方を繰り返し示す。
  - 正解へのたどり着き方を主役にする：`steps` で手順、`evidence` で本文のどの文のどの語句が決め手か、`choices` で全選択肢の訳と正誤の理由。
  - 誤答は「本文のどことどうずれるか（`why`）」と「これを選ぶ人の思考（`who`）」を必ず両方書く。
  - 「つまり」（`gist`）は訳の言い直しではなく、その段落が文章の流れの中で何をしているかまで書く。
  - 失点の型は、知識の不足ではなく「どの手がかりを見落としたか」で分ける。

## 見た目（このシリーズはカラー）

Web 版解説（`gakushuin-university-2022-english-q2-full.html`）の配色を印刷向けに移したもの。

- 色は 紺（主色 #16263f）＋ 金（#b8954a）・緑（#1f6b5c）・朱（#c8431f）だけ。
- **色を着けすぎない。** 地の大部分は白。色は要所だけに使う：章見出しの紺の帯（金の下線）、節見出しの金の左線、設問カード（紺の左線）、囲みの左線と札の文字色、正解の強調（緑）、誤答の × と罠（朱）、表の見出し行（紺）。薄い地色を敷くのは「この文章の正体」（金）と「要注意の罠」（朱）、全選択肢の表の正解の行（ごく薄い緑）、全訳の「つまり」の囲み（ごく薄い緑。旧データではかみくだいた訳の列）、根拠の文の決め手の語句（蛍光ペン風の薄い黄）だけ。
- 構文の図の働き：S＝紺、V＝朱、O・C＝緑、M＝金、関係詞などは灰。行の左線もその色。
- 根拠の文：場所（緑の小見出し）→ 英文｜訳を左右に並べた枠 → 「決め手」の一行。決め手の語句（`**…**`）は英文・訳とも蛍光ペン風。
- 全選択肢の表：記号（正解＝緑の ○、誤答＝朱の ×）｜英語（英文書体）と訳（灰）｜理由（「なぜ正解か」緑／「どこがずれるか」朱）＋誤答は「選ぶ人の思考」。
- 全訳（v2）：段落の見出し（金の上線）→ 全訳（文番号①②…は金）→ その下に「つまり」の囲み（ごく薄い緑の地＋緑の左線）。旧データは従来どおり、原文に忠実な訳＝紺の見出し、かみくだいた訳＝緑の見出し＋ごく薄い緑の列。
- 崩れ防止：負の `text-indent` は使わない。札・バッジは inline の色付き太字か、ブロック（div）で作る（背景・枠つきの inline-block は欠ける）。長い囲み・設問カードはページで割れてよい（割れ目にも線と余白が付く）。見出しと「構文の確認（精読）」の最初の構文の図、根拠の文の場所の行、全訳の段落見出しは、ページ末に取り残されないよう次ページへ送る。「つまり」の囲みは割らない。

## 表紙

A4 縦 1 ページ。単色の地（`cover_color`、落ち着いた深い色 1 色）＋白文字、太い白帯 1 本。
上部の小さな行「学部別・逆算戦略設計 THINKING」、中央に大学名・学部、その下に「〇〇年度 科目」、帯の下にシリーズ名「THINKINGの徹底解説シリーズ」。グラデーション・影・角丸・写真は使わない。

## 引き継ぎ・保存のしくみ（作業環境は消える前提）

- 中身（訳・解説データ・過去問・分析）は**リポジトリに入れない**（main は Netlify で全公開。リポジトリ自体も public）。
- 保存先はドライブ「THINKING 作業データ（非公開）」。新しいセッションは最初に同フォルダの「00_【最新】引き継ぎ書」を読む。
- ドライブは1回のアップロードが約3MBまでなので、`tools/drive_pack.py` で分割して預ける。
  - 預ける: `python3 tools/drive_pack.py pack <名前> <出力先> <対象...>` → part と manifest を全部ドライブへ（変換なし）
  - 戻す: ドライブから part と manifest を同じフォルダに落として `python3 tools/drive_pack.py restore <manifest> <展開先>`（sha256 照合つき）
- 作業の区切りごとに必ず預ける（納品・大問ごとの完成・セッション終了前）。
