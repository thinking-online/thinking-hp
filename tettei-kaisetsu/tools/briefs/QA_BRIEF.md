# 独立QAの共通指示（THINKINGの徹底解説シリーズ）

あなたは完成した解説PDF（1年度分）の独立QA担当。書いた人ではない。疑ってかかる。

## 対象（<年度フォルダ> と <id> は依頼文で指定）
- PDF：<年度フォルダ>/content/out/<id>.pdf（ページ画像は <年度フォルダ>/out_png/page-NNN.png。文字は `pdftotext -layout`）
- 中身：<年度フォルダ>/content/data/<id>.py と <年度フォルダ>/content/parts/part1.py〜part5.py
- 問題冊子（英文の正本）：<年度フォルダ>/src/p-*.png（必要なら `pdftoppm -r 200` で拡大）
- 確定解答：<年度フォルダ>/work/answer_key_final.md
- 開かない：<年度フォルダ>/src/answer.pdf・ans-*.png・work/ref_key.md・note/ 内の英文書き起こし

## 確認すること
1. 全設問の答え（設問・解答一覧・自己採点表）が確定解答と一致。メモの「割れる問題」「参考解答と不一致」の扱いが解説・照合欄・冒頭の注で食い違っていない。
2. 引用した英語（根拠・選択肢・下線部）が問題冊子と一字一句同じ。loc（第n段落第m文／発話n）が正しい。
3. 解説が本文と事実として合っている。why・steps・マップ・全訳の間に矛盾がない。段落番号の誤りがない。
4. 全訳の誤訳（文体ではなく意味の誤り）。
5. 冒頭（data ファイル）の数字が各大問と一致：大問ごとの語数（body_words と冒頭の表）、設問数・マーク数・記述数、配点の合計、目安時間（表の合計90分・各大問の lead や types_note に書いた分数）。食い違えば、冒頭の表・lead・注を実際の大問に合わせて直す（body_words は本文に近い方へ）。
6. 他社名（赤本・青本・旺文社・東進・河合・駿台・教学社・予備校名・塾名）がない。解答の出どころは「市販の解答」だけ。
7. 全訳の gist が「つまり、」で始まっていれば、その「つまり、」を消す（見出しに「つまり」と出るため重複になる）。
8. レイアウト：ページ画像で欠け・重なり・最終ページ以外のほぼ空白のページを確認。

## 直し方
客観的な誤りは .py を Edit で直す（スキーマを守る。英語の量の制限を守る）。答えは変えない（答えが誤りだと思えば根拠つきで報告）。直したら再ビルド：
`cd /home/user/thinking-hp/tettei-kaisetsu && python3 build.py <id> --content-dir <年度フォルダ>/content --out <年度フォルダ>/content/out/<id>.pdf --png <年度フォルダ>/out_png`
ERROR 0 を確認。

## 報告
(a) 直したもの（ファイル・場所・前→後を短く）、(b) 直さなかった疑問（理由）、(c) 最終ビルド（ページ数・ERROR/WARN 数）。

## 出力の注意（重要）
英文を長く書き写すと出力がフィルターで止まり、作業が失われる。照合のメモでも英文は短い断片だけにし、日本語で考える。報告にも英文を長く引用しない。
